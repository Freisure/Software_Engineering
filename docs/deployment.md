# 部署、操作与维护手册

## 1. 本机演示

Windows安装Python 3.12或更高版本并加入PATH。在项目目录双击 `start.bat`。若随本地交付已包含 `.packages/`，直接使用已备好的依赖；GitHub源码不包含依赖，首次运行会创建虚拟环境并安装依赖。访问 `http://127.0.0.1:5000`。

启动窗口需保持运行，Ctrl+C停止服务。端口冲突时在启动前设置 `PORT=5001`，访问对应端口。数据库和图片在 `instance/`；不要删除此目录作为日常重启方式。

## 2. 正式环境初始化

不用 `start.bat`（该脚本明确用于演示）。建立虚拟环境，安装 `requirements.txt`，不设置 `CAMPUS_DEMO`，再执行：

```text
python manage.py create-admin admin2026 --name 学院管理员
python app.py
```

管理员密码采用交互输入。首次创建正式环境应使用全新数据库，不能直接把包含演示账号的数据库暴露到公网。管理员通过课程库页面添加本校真实课程；学生自行注册。无需修改源码设置管理员密码。

| 环境变量 | 含义 | 默认 |
|---|---|---|
| CAMPUS_DEMO | 仅值1启用演示初始化 | 关闭 |
| HOST | 服务绑定地址 | 127.0.0.1 |
| PORT | 端口 | 5000 |
| SECRET_KEY | Cookie签名密钥 | 本地随机生成并保存在instance/.secret |
| COOKIE_SECURE | 值1时仅HTTPS发送Cookie | 关闭，供本机HTTP演示 |

校内服务器通过反向代理提供HTTPS，保留原始Host；将 `COOKIE_SECURE=1`。当前应用的Origin检查使用请求Host和scheme，代理需要正确传递协议信息，或在代理到应用间也使用HTTPS。若采用TLS终止代理，应明确配置受信代理后再上线，不能无条件信任外部转发头。项目默认仅本机运行，不代为部署公网服务器。

## 3. 备份与恢复

运行 `python manage.py backup` 会生成唯一时间目录，已存在目标目录会拒绝覆盖。采用SQLite在线备份API，数据库快照包含已提交的WAL内容；图片同步复制。密钥不包含在备份中，应由服务器管理者另行保管。

每日备份可在Windows任务计划程序中设置程序为虚拟环境python，参数 `manage.py backup`，起始目录为项目目录。Linux可用cron定时运行同一命令。课程演示可手动执行一次模拟每日备份。建议定期恢复验证，备份含用户资料，不提交到公开Git仓库。

恢复步骤：停止服务；将当前 `instance/` 改名留存；将备份的 `campus.db` 和 `uploads/` 复制进新的 `instance/`；恢复原密钥或允许生成新密钥（用户需重新登录）；启动后核对教材与交接数据。不要在服务运行中直接覆盖数据库文件。

`python manage.py expire` 执行超时待确认检查，可每小时调度。默认也会在用户或管理员访问预约列表时执行。

## 4. 学生使用说明

注册时填写学号、昵称、学院、班级和至少8位密码。学院不是认证凭据；校内身份真实性由实际部署方管理。个人中心维护联系方式，勿在教材图片里写手机号。

发布时关联正确课程，照片应能看清版次和书况；价格填0表示赠送。审核失败可查看理由、编辑重提。教材处于有效预约状态时不能修改，防止交易信息改变。

发起预约后等发布者接受。双方按约定线下见面，开始交接后各自确认。对方未确认时不要重复提交；可申诉等待管理员。完成后评价对方，删除评价后不能再次刷评。

## 5. 管理员使用说明

审核教材课程、版次、图片与联系方式；驳回必须说明原因。处理举报应先核实证据，成立可扣分并下架；下架会取消有效预约。处罚申诉成立会退还原实际扣分，但教材保持下架，需修改后重审。

交接申诉可裁定完成、取消或爽约；爽约须选择正确责任方。统计与日志可辅助核对，不能替代线下事实核实。日志界面展示最近500条，数据库保留全部记录。

## 6. 运维边界

本项目定位课程规模，未提供生产级监控、邮件通知、多租户隔离、自动清理孤立上传或数据库版本迁移系统。公开部署前应核实校园账号管理规则、隐私告知、日志保留期与服务器备份权限。列表目前不分页，千级数据性能以测试报告为准。
